# RAG Use Cases & Algorithms Guide

Цей посібник створено для того, щоб надати загальне розуміння того, як різні алгоритми пошуку та архітектури застосовуються на практиці в RAG (Retrieval-Augmented Generation), а також які популярні інструменти їх використовують.

---

## Який алгоритм пошуку обрати?

Успіх RAG-системи майже повністю залежить від того, наскільки якісно працює етап Retrieval (пошуку). Різні задачі вимагають різних алгоритмів.

### 1. Лексичний пошук (BM25)

Шукає за точним збігом ключових слів (exact keyword match), враховуючи їхню рідкісність (Term Frequency / Inverse Document Frequency).

* **Коли працює найкраще:**
  * Пошук конкретних ідентифікаторів (наприклад, `INC-2023-Q4`, `ERR_MEM_ALLOC_FAIL_0x80`).
  * Пошук за точними іменами, артикулами товарів, серійними номерами.
  * Пошук у технічних логах (Log analysis).
* **Use Case:** Внутрішня система підтримки інженерів, де потрібно швидко знаходити документацію за кодом помилки, який вивів компілятор.

### 2. Векторний пошук (Vector Search / ANN / kNN)

Перетворює текст на багатовимірні координати (Embeddings) і шукає за семантичною близькістю (Cosine similarity).

* **Коли працює найкраще:**
  * Пошук за змістом, концепціями, синонімами.
  * Коли користувач ставить запитання природною мовою, яке може бути сформульовано по-різному (наприклад, "Як налаштувати мережу?" замість "Network configuration manual").
* **Use Case:** Чат-бот для клієнтів (Customer Support), який відповідає на загальні запитання про повернення товару, незалежно від того, як клієнт сформулював своє питання.

### 3. Гібридний пошук (Hybrid Search з RRF)

Об'єднує результати BM25 та Vector Search за допомогою Reciprocal Rank Fusion, щоб нівелювати недоліки обох методів.

* **Коли працює найкраще:**
  * General-purpose RAG (загальнопризначені системи).
  * Коли база знань містить як текст, так і технічні терміни/ідентифікатори.
* **Use Case:** Корпоративна Wiki (наприклад, Confluence). Користувач може шукати як точну назву проєкту "Project Zircon", так і загальне питання "Яка політика відпусток?".

### 4. Reranking (Cross-encoder)

Повільний, але надзвичайно точний алгоритм, який бере топ-100 результатів швидкого пошуку і переоцінює їх, аналізуючи запит і кожен документ одночасно.

* **Коли працює найкраще:**
  * Коли потрібна найвища можлива точність (High Precision).
  * Юридичні та медичні RAG-системи, де ціна помилки дуже висока.
* **Use Case:** Асистент юриста, який аналізує тисячі судових рішень. Система спочатку знаходить 100 схожих справ через векторний пошук, а потім Reranker вибирає 5 справ, які ідеально відповідають нюансам запиту.

### 5. Алгоритми Промптингу та Міркування (Prompting & Reasoning)

Хоча це не алгоритми "пошуку" в традиційному розумінні, вони визначають, як модель обробляє знайдену інформацію та приймає рішення (що є основою Agentic Search).

* **Коли працює найкраще:**
  * Коли недостатньо просто знайти текст, а потрібно зробити багатоетапний аналіз.
  * Для створення агентів, які можуть самостійно шукати дані в інтернеті чи базах.
* **Основні види:**
  * **Chain-of-Thought (CoT):** Змушує модель думати "крок за кроком". Ідеально для логічних та математичних задач.
  * **ReAct (Reason + Act):** Цикл, де модель розмірковує, викликає інструмент (наприклад, пошук), оцінює результат і діє далі. Основа AI-агентів.
  * **Self-consistency:** Генерація кількох CoT-відповідей та вибір тієї, яка зустрічається найчастіше (majority vote). Мінімізує галюцинації у складних задачах.

## Як популярні інструменти використовують ці алгоритми?

Сучасні AI-продукти рідко використовують лише один алгоритм. Зазвичай це складна комбінація пошуку, роутингу та промпт-інжинірингу (ReAct, CoT).

### Claude Code

Інструмент для роботи з кодом (Agentic Coding).

* **Алгоритми:** Використовує **ReAct** (цикл Reason + Act) для виклику інструментів читання файлів. Для пошуку по кодовій базі активно застосовує **Hybrid Search**: BM25 для пошуку конкретних назв функцій чи змінних, та Vector Search для пошуку логіки ("де у нас зберігаються паролі?").

### Notebook LLM (від Google)

Застосунок для аналізу ваших власних документів.

* **Алгоритми:** Класичний **RAG** із потужним **Vector Search** під капотом (через екосистему Google). Може використовувати **Self-consistency** або **Chain-of-Thought (CoT)**, щоб генерувати конспекти та гарантувати, що відповіді базуються *виключно* на завантажених PDF-файлах (Grounding).

### Gemini Deep Research (від Google)

Інструмент для глибокого дослідження тем в інтернеті.

* **Алгоритми:** Це агентна система. Вона використовує **ReAct** для прийняття рішень про те, які пошукові запити виконати. Після отримання сотень сторінок з інтернету, застосовується **RAG** з потужним **Reranking**, щоб відібрати найкорисніші абзаци з різних джерел. Також використовується **CoT** для планування дослідження.

### ChatGPT (з інструментами Web Search / Code Interpreter)

Базовий ChatGPT з підключеним пошуком.

* **Алгоритми:** Використовує агенту архітектуру, схожу на **ReAct**, щоб вирішувати, коли потрібно звернутися до Bing Search. Для пошуку по минулих розмовах (Memory) використовується **Vector Search**.

### DeepSeek (наприклад, DeepSeek-R1)

Моделі, оптимізовані для програмування та глибоких роздумів.

* **Алгоритми:** Модель R1 (Reasoning 1) стала відомою завдяки екстремальному використанню **Chain-of-Thought (CoT)** безпосередньо на етапі навчання (Reinforcement Learning). Вона змушена думати крок за кроком перед тим, як дати відповідь. Якщо підключити її до кодової бази, вона працюватиме як ядро агента в архітектурі **ReAct**.

### Perplexity AI

Пошукова система нового покоління (Search Engine).

* **Алгоритми:** Це найдосконаліший публічний приклад **Hybrid RAG** у реальному часі. Використовує лексичний пошук (Bing/Google) для знаходження сторінок, швидкий векторний пошук для обробки цих сторінок "на льоту", і обов'язково **Cross-encoder (Reranking)**, щоб виділити найкращі факти, з яких генерується підсумкова відповідь із цитатами.

### Pinecone / ChromaDB / Qdrant

Векторні бази даних.

* **Алгоритми:** Це інфраструктурні інструменти, які реалізують індекси **ANN (Approximate Nearest Neighbors)**, зокрема алгоритми **HNSW** та **IVF-PQ**. Вони дозволяють векторному пошуку працювати з мільйонами документів за мілісекунди, замість використання повільного Brute-force kNN. Багато з них зараз додають вбудовану підтримку **BM25**, стаючи повноцінними гібридними базами (Hybrid Vector Databases).
