# Оцінка підказок (Prompt evaluation)

При роботі з Claude написання хорошої підказки - це лише початок. Щоб створювати надійні AI-додатки, вам потрібно розуміти дві важливі концепції: інженерію підказок (prompt engineering) та оцінку підказок (prompt evaluation). Інженерія підказок дає вам методи для написання кращих підказок, тоді як оцінка підказок допомагає виміряти, наскільки добре ці підказки насправді працюють.

## Інженерія підказок проти Оцінки підказок

Інженерія підказок - це ваш набір інструментів для створення ефективних підказок. Вона включає такі методи, як:

- Багатокрокові підказки (Multishot prompting)  
- Структурування за допомогою тегів XML  
- Багато інших найкращих практик

Ці методи допомагають Claude зрозуміти, що саме ви просите і як ви хочете, щоб він відповів.

Оцінка підказок має інший підхід. Замість того, щоб зосереджуватися на тому, як писати підказки, йдеться про вимірювання їхньої ефективності за допомогою автоматизованого тестування. Ви можете:

- Тестувати на основі очікуваних відповідей  
- Порівнювати різні версії однієї підказки  
- Перевіряти результати на наявність помилок

---

## Три шляхи після написання підказки

Після того, як ви склали підказку, перед вами зазвичай постає три варіанти того, що робити далі:

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623382%2F04_-_001_-_Prompt_Evaluation_10.1748623382207.png)  
Варіант 1: Протестувати підказку один раз і вирішити, що вона достатньо хороша. Це несе значний ризик поломки у продакшені, коли користувачі надають неочікувані вхідні дані.

Варіант 2: Протестувати підказку кілька разів і налаштувати її для обробки одного-двох крайніх випадків (corner cases). Хоча це краще за варіант 1, користувачі часто надаватимуть дуже неочікувані результати, які ви не врахували.

Варіант 3: Пропустити підказку через конвеєр оцінювання (evaluation pipeline), щоб оцінити її, а потім ітеративно вдосконалювати підказку на основі об'єктивних показників. Цей підхід вимагає більше зусиль і витрат, але дає вам набагато більше впевненості у надійності вашої підказки.

---

## Чому більшість інженерів потрапляють у пастки тестування

Варіанти 1 і 2 - це поширені пастки, в які потрапляють усі інженери, включно зі мною. Це цілком природно - написати підказку для серйозного додатка і не протестувати її достатньо ретельно. Ми схильні недооцінювати, зі скількома граничними випадками (edge cases) зіткнуться реальні користувачі.

Реальність така, що коли ви розгортаєте підказку у продакшені, користувачі взаємодіятимуть з нею у способи, які ви ніколи не передбачали. Те, що здавалося надійною підказкою під час вашого обмеженого тестування, може швидко зламатися, зіткнувшись із повною різноманітністю реальних вхідних даних.

---

## Підхід, орієнтований на оцінку (Evaluation-First)

Варіант 3 представляє собою більш систематичний підхід до розробки підказок. Пропускаючи вашу підказку через конвеєр оцінювання, ви отримуєте об'єктивні показники її продуктивності для ширшого діапазону тестових випадків. Цей підхід, керований даними, дозволяє вам:

- Виявляти слабкі місця до того, як вони стануть проблемами у продакшені  
- Об'єктивно порівнювати різні версії підказок  
- Впевнено ітерувати на основі вимірюваних покращень  
- Створювати більш надійні AI-додатки

Хоча цей підхід вимагає більше початкових інвестицій часу та інфраструктури для тестування, він окупається у вигляді надійності та стійкості вашого кінцевого додатка. Мета полягає в тому, щоб виявляти проблеми під час розробки, а не після того, як з ними зіткнуться ваші користувачі.

## Функція run_prompt

Ця функція бере тестовий випадок і об'єднує його з нашим шаблоном підказки:

```python
def run_prompt(test_case):  
    """Об'єднує підказку та вхідні дані тестового випадку, потім повертає результат"""  
    prompt = f"""  
Будь ласка, виріши наступне завдання:

{test_case["task"]}  
"""  
      
    messages = []  
    add_user_message(messages, prompt)  
    output = chat(messages)  
    return output
```

## Функція run_eval

Ця функція координує весь процес оцінювання:

```python
def run_eval(dataset):  
    """Завантажує набір даних і викликає run_test_case для кожного випадку"""  
    results = []

        result = run_test_case(test_case)

    return results
```

Ця функція обробляє кожен тестовий випадок у нашому наборі даних і збирає всі результати в єдиний список.

## Типи грейдерів

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623451%2F04_-_005_-_Model_Based_Grading_03.1748623451557.png)  
Існує три основні підходи до оцінювання виводу моделей:

- Кодові грейдери (Code graders) - Програмно оцінюють вивід, використовуючи власну логіку  
- Модельні грейдери (Model graders) - Використовують іншу модель AI для оцінки якості  
- Людські грейдери (Human graders) - Люди вручну перевіряють та оцінюють результати

### Кодові грейдери

Кодові грейдери дозволяють вам реалізувати будь-яку програмну перевірку, яку ви можете уявити. Поширені способи використання включають:

- Перевірка довжини виводу  
- Перевірка наявності/відсутності певних слів у виводі  
- Перевірка синтаксису для JSON, Python або regex  
- Оцінка читабельності

Єдина вимога полягає в тому, що ваш код повертає певний корисний сигнал - зазвичай число від 1 до 10.

### Модельні грейдери

Модельні грейдери передають ваш оригінальний вивід в інший виклик API для оцінки. Цей підхід пропонує величезну гнучкість для оцінки:

- Якості відповіді  
- Якості виконання інструкцій  
- Повноти  
- Корисності  
- Безпеки

### Людські грейдери

Людські грейдери забезпечують найбільшу гнучкість, але потребують багато часу і є виснажливими. Вони корисні для оцінки:

- Загальної якості відповіді  
- Всебічності  
- Глибини  
- Лаконічності  
- Релевантності

## Інтеграція оцінювання у ваш робочий процес

```python
def run_test_case(test_case):

    # Оцінюємо вивід  
    model_grade = grade_by_model(test_case, output)

        "test_case": test_case,
```

Нарешті, обчисліть середній бал за всіма тестовими випадками:

```python
from statistics import mean

def run_eval(dataset):  
    results = []  
      
    for test_case in dataset:  
        result = run_test_case(test_case)  
        results.append(result)  
      
    average_score = mean([result["score"] for result in results])  
    print(f"Середній бал: {average_score}")  
      
    return results
```

Це дає вам об'єктивну метрику для відстеження в процесі вдосконалення вашої підказки. Хоча модельні грейдери можуть бути дещо примхливими, вони забезпечують послідовну базу для вимірювання покращень.

## Як працює кодове оцінювання

Кодове оцінювання перевіряє два ключові аспекти відповідей, згенерованих AI:

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623444%2F04_-_006_-_Code_Based_Grading_00.1748623444116.png)

Перші два критерії обробляються кодовим грейдером, тоді як виконання завдання оцінюється модельним грейдером. Разом вони забезпечують всебічну оцінку.

## Функції перевірки синтаксису

Щоб перевірити, чи згенерований код має дійсний синтаксис, ви можете створити три допоміжні функції, які намагаються розпарсити вивід:

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623445%2F04_-_006_-_Code_Based_Grading_02.1748623445106.png)

```python
def validate_json(text):  
    try:  
        json.loads(text.strip())  
        return 10  
    except json.JSONDecodeError:  
        return 0

def validate_python(text):  
    try:  
        ast.parse(text.strip())  
        return 10  
    except SyntaxError:  
        return 0

def validate_regex(text):  
    try:  
        re.compile(text.strip())  
        return 10  
    except re.error:
        return 0
```

Кожна функція намагається розпарсити текст у відповідному форматі. Якщо парсинг проходить успішно, вона повертає ідеальний бал 10. Якщо це не вдається і виникає помилка, синтаксис є недійсним і повертається 0.
