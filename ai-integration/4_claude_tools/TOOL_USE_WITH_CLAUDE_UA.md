# Введення у використання інструментів (Introducing tool use)

Інструменти дозволяють Клоду отримувати доступ до інформації із зовнішнього світу, розширюючи його можливості за межі того, що він вивчив під час навчання. За замовчуванням, Клод знає лише інформацію зі своїх навчальних даних і не має доступу до поточних подій, даних у реальному часі або зовнішніх систем. Використання інструментів вирішує це обмеження, створюючи структурований спосіб для Клода запитувати та отримувати свіжу інформацію.

## Проблема без інструментів (The Problem Without Tools)

Коли користувачі запитують Клода про поточну інформацію, він стикається зі стіною. Наприклад, якщо хтось запитує "Яка зараз погода в Сан-Франциско, Каліфорнія?", Клод змушений відповідати щось на зразок "Вибачте, але я не маю доступу до актуальної інформації про погоду."

![image_2_1](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623642%2F06_-_001_-_Introducing_Tool_Use_05.1748623642311.png)

**💡 Tips (Коли потрібні інструменти)**: Використовуйте інструменти тоді, коли відповідь вимагає свіжих даних, розрахунків або взаємодії з вашою бізнес-логікою.
**🚀 Use cases (Отримання інформації у реальному часі)**: Інтеграція з погодними сервісами, фінансовими біржами або системами бронювання.

Це створює розчарування у користувачів, коли їм потрібні дані в реальному часі, з якими Клод теоретично міг би допомогти, якби мав доступ до поточної інформації.

## Як працює використання інструментів (How Tool Use Works)

Використання інструментів слідує специфічному патерну взаємодії туди-сюди між вашим додатком та Клодом. Ось повний потік:

![image_3_1](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623643%2F06_-_001_-_Introducing_Tool_Use_07.1748623643055.png)

1. **Початковий запит (Initial Request)**: Ви надсилаєте Клоду запитання разом з інструкціями про те, як отримати додаткові дані із зовнішніх джерел.
2. **Запит інструмента (Tool Request)**: Клод аналізує запитання і вирішує, що йому потрібна додаткова інформація, після чого просить конкретні деталі про те, які дані йому потрібні.
3. **Отримання даних (Data Retrieval)**: Ваш сервер запускає код для отримання запитаної інформації із зовнішніх API або баз даних.
4. **Фінальна відповідь (Final Response)**: Ви надсилаєте отримані дані назад Клоду, який потім генерує повну відповідь, використовуючи як початкове запитання, так і свіжі дані.

**🚀 Use cases (Інтеграція з API)**: Створення чат-бота для туристів, який автоматично перевіряє погоду та завантаженість готелів.

## Ключові переваги (Key Benefits)

- **Інформація в реальному часі**: Доступ до поточних даних, які не були доступні під час навчання Клода.
- **Інтеграція із зовнішніми системами**: Підключення Клода до баз даних, API та інших сервісів.
- **Динамічні відповіді**: Надання відповідей на основі найсвіжішої доступної інформації.
- **Структурована взаємодія**: Клод точно знає, яка інформація йому потрібна і як її запитати.

Використання інструментів перетворює Клода зі статичної бази знань на динамічного асистента, який може працювати з живими даними. Це відкриває можливості для створення додатків, що потребують поточної інформації, чи то даних про погоду, курсів акцій, запитів до бази даних або будь-якої іншої інформації в реальному часі, яка може знадобитися вашим користувачам.

**💡 Tips (Переваги динамічних відповідей)**: Чим краще ви опишете інструмент, тим точнішими і кориснішими будуть динамічні відповіді моделі.
**🚀 Use cases (Додатки для біржових цін або баз даних)**: Фінансові асистенти, які генерують звіти на основі живих котирувань.

![image_7_1](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623630%2F06_-_002_-_Project_Overview_00.1748623629884.png)

Мета проста: ми хочемо сказати Клоду "Встанови нагадування про мій візит до лікаря. Це через тиждень з цього четверга" і отримати відповідь від Клода: "ОК, я нагадаю вам." Але щоб це запрацювало, нам потрібно вирішити деякі обмеження в тому, як Клод обробляє час і нагадування.

### Чому це складно (Why This Is Challenging)

Хоча Клод знає поточну дату, є три специфічні проблеми, які нам потрібно вирішити:

- **Обмежена обізнаність про час**: Клод може знати поточну дату, але не точний час.
- **Проблеми з обчисленням дат**: Клод не завжди добре справляється з додаванням, пов'язаним з часом, особливо коли йдеться про багато днів у майбутньому.
- **Відсутність можливості нагадування**: Клод не знає, як встановити нагадування - у нього немає вбудованого механізму для цього.

Кожне з цих обмежень є прогалиною між тим, що Клод може робити від природи, і тим, що нам потрібно для нашої системи нагадувань. Інструменти - це те, як ми долаємо ці прогалини.

**💡 Tips (Розуміння обмежень моделі)**: Не намагайтеся змусити модель обчислювати складні дати самостійно; краще надайте їй інструмент для математики або роботи з датами.
**🚀 Use cases (Системи керування завданнями)**: Асистенти продуктивності, які планують зустрічі в календарі на основі запитів природною мовою.

Цей проєкт демонструє ключовий принцип роботи з ШІ: коли модель має обмеження, ми розширюємо її можливості за допомогою інструментів, а не намагаємося обійти ці обмеження у наших промптах.

**💡 Tips (Поступова реалізація інструментів)**: Розбивайте складні завдання на простіші, атомарні інструменти, які легко тестувати.
**🚀 Use cases (Комплексні багатоетапні завдання)**: Створення розумного планувальника, який самостійно знаходить вільний час і надсилає запрошення.

### Що таке функції інструментів? (What Are Tool Functions?)

Функція інструмента - це звичайна Python-функція, яка виконується автоматично, коли Клод вирішує, що йому потрібна додаткова інформація для допомоги користувачеві. Наприклад, якщо хтось запитує "Котра зараз година?", Клод викличе ваш інструмент дати/часу, щоб отримати поточний час.

Ось приклад функції інструмента для погоди. Зверніть увагу, як вона перевіряє вхідні дані та надає зрозумілі повідомлення про помилки - це важливі найкращі практики.

### Найкращі практики для функцій інструментів (Best Practices for Tool Functions)

При написанні функцій інструментів дотримуйтесь таких рекомендацій:

- **Використовуйте описові імена**: Як ім'я вашої функції, так і імена параметрів повинні чітко вказувати на їх призначення.
- **Перевіряйте вхідні дані**: Перевірте, чи не є обов'язкові параметри порожніми або недійсними, і викликайте помилки, якщо вони такі.
- **Надавайте зрозумілі повідомлення про помилки**: Клод може бачити повідомлення про помилки і може спробувати викликати функцію знову з виправленими параметрами.

Валідація особливо важлива, оскільки Клод вчиться на помилках. Якщо ви викликаєте чітку помилку на кшталт "Location cannot be empty", Клод може спробувати викликати функцію ще раз із правильним значенням локації.

**💡 Tips (Валідація та обробка помилок)**: Завжди пишіть детальні повідомлення про помилки, щоб ШІ зрозумів, що пішло не так і як це виправити.
**🚀 Use cases (Створення власних функцій інструментів)**: Безпечне виконання скриптів, де валідація на стороні Python запобігає передачі некоректних даних у базу.

## Створення вашої першої функції інструмента (Building Your First Tool Function)

Давайте створимо функцію для отримання поточної дати та часу. Ця функція прийматиме параметр `date_format`, щоб Клод міг запитувати час у різних форматах:

```python
def get_current_datetime(date_format="%Y-%m-%d %H:%M:%S"):
    if not date_format:
        raise ValueError("date_format cannot be empty")
    return datetime.now().strftime(date_format)
```

Ця функція використовує модуль Python `datetime` для отримання поточного часу і форматує його відповідно до наданого рядка формату. Формат за замовчуванням дає нам рік-місяць-день година:хвилина:секунда.

Ви можете протестувати її з різними форматами:

```python
# Default format: "2024-01-15 14:30:25"
get_current_datetime()

# Just hour and minute: "14:30"
get_current_datetime("%H:%M")
```

Перевірка валідації гарантує, що Клод не зможе передати порожній рядок для формату дати. Хоча ця конкретна помилка малоймовірна, вона демонструє шаблон перевірки вхідних даних та надання корисних повідомлень про помилки, з яких Клод може навчитися.

### Наступні кроки (Next Steps)

Створення функції - це лише перший крок. Далі вам потрібно написати JSON-схему, яка описує функцію для Клода, а потім інтегрувати її у вашу систему чату. Цей підхід з функціями інструментів надає Клоду потужні можливості, зберігаючи при цьому ваш код організованим і придатним для обслуговування.

**💡 Tips (Використання стандартних модулів Python)**: Чим простіше функція з точки зору стандартних бібліотек, тим надійніше вона працюватиме як інструмент для ШІ.
**🚀 Use cases (Отримання точного локального часу)**: Автоматичне проставлення міток часу на звітах, створених асистентом.

## Схеми інструментів (Tool schemas)

Після написання вашої функції інструмента, наступний крок - створення JSON-схеми, яка каже Клоду, які аргументи очікує ваша функція і як її використовувати. Ця схема діє як документація, яку Клод читає, щоб зрозуміти, коли і як викликати ваші інструменти.

### Розуміння JSON-схеми (Understanding JSON Schema)

JSON Schema не є специфічною для ШІ або виклику інструментів - це широко використовувана специфікація валідації даних, яка існує вже багато років. Спільнота ШІ прийняла її, оскільки це зручний спосіб описати параметри функцій та перевірити дані.

![image_16_1](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623699%2F06_-_004_-_Tool_Schemas_01.1748623699583.png)

Повна специфікація інструмента має три основні частини:

- **name** - Чітке, описове ім'я для вашого інструмента (наприклад, "get_weather")
- **description** - Що робить інструмент, коли його використовувати, і що він повертає
- **input_schema** - Фактична JSON-схема, що описує аргументи функції

### Написання ефективних описів (Writing Effective Descriptions)

Опис вашого інструмента є критично важливим для того, щоб допомогти Клоду зрозуміти, коли використовувати вашу функцію. Найкращі практики включають:

- Прагніть до 3-4 речень, які пояснюють, що робить інструмент
- Опишіть, коли Клод повинен його використовувати
- Поясніть, який тип даних він повертає
- Надайте детальні описи для кожного аргументу

**💡 Tips (Важливість точного опису)**: Якщо модель викликає інструмент не тоді, коли потрібно, перш за все, деталізуйте його `description`.
**🚀 Use cases (Документування API)**: Створення універсальних агентів, які читають описи ендпоінтів і розуміють, куди відправляти запити.

## Простий спосіб створення схем (The Easy Way to Generate Schemas)

Замість того, щоб писати JSON-схеми з нуля, ви можете використовувати самого Клода для їх генерації. Ось процес:

1. Скопіюйте код вашої функції інструмента

3. Включіть документацію Anthropic про використання інструментів як контекст

### Впровадження схеми в код (Implementing the Schema in Code)

Коли Клод згенерує вашу схему, скопіюйте її у ваш файл з кодом. Ось хороший шаблон іменування для наслідування:

```python
def get_current_datetime(date_format="%Y-%m-%d %H:%M:%S"):
    if not date_format:
        raise ValueError("date_format cannot be empty")
    return datetime.now().strftime(date_format)

get_current_datetime_schema = {
    "name": "get_current_datetime",
    "description": "Returns the current date and time formatted according to the specified format",
    "input_schema": {
        "type": "object",
        "properties": {
            "date_format": {
                "type": "string",
                "description": "A string specifying the format of the returned datetime. Uses Python's strftime format codes.",
                "default": "%Y-%m-%d %H:%M:%S"
            }
        },
        "required": []
    }
}
```

Використовуйте шаблон `function_name` з наступним `function_name_schema`, щоб ваші схеми були організовані і їх було легко зіставити з відповідними функціями.

### Додавання безпеки типів (Adding Type Safety)

Для кращої перевірки типів імпортуйте та використовуйте тип `ToolParam` з бібліотеки Anthropic:

```python
from anthropic.types import ToolParam

get_current_datetime_schema = ToolParam({
    "name": "get_current_datetime",
    "description": "Returns the current date and time formatted according to the specified format",
    # ... rest of schema
})
```

Хоча це не є строго необхідним для функціональності, це запобігає помилкам типів, коли ви використовуєте схему з API Клода, і робить ваш код більш надійним.

**💡 Tips (Генерація схем за допомогою ШІ)**: Використовуйте ШІ для рутинної роботи зі складання схем — це зекономить години часу на пошук синтаксичних помилок у JSON.
**🚀 Use cases (Типізація за допомогою Anthropic SDK)**: Розробка великих Python-проєктів з Mypy або Pydantic для суворого контролю форматів.

## Обробка блоків повідомлень (Handling message blocks)

Працюючи з функціональністю інструментів Клода, ви зіткнетеся з новим типом структури відповідей, яка відрізняється від простих текстових відповідей, які ви бачили раніше. Замість того, щоб просто отримувати один текстовий блок, Клод тепер може повертати багатоблокові повідомлення, які містять як текст, так і інформацію про використання інструменту.

### Виконання API-запитів з підтримкою інструментів (Making Tool-Enabled API Calls)

Щоб дозволити Клоду використовувати інструменти, вам потрібно додати параметр `tools` у ваш API-запит. Ось як структурувати запит:

```python
messages = []
messages.append({
    "role": "user",
    "content": "What is the exact time, formatted as HH:MM:SS?"
})

response = client.messages.create(
    model=model,
    max_tokens=1000,
    messages=messages,
    tools=[get_current_datetime_schema],
)
```

Параметр `tools` приймає список JSON-схем, які описують доступні функції, які може викликати Клод.

### Розуміння багатоблокових повідомлень (Understanding Multi-Block Messages)

Коли Клод вирішує використати інструмент, він повертає повідомлення асистента з кількома блоками у списку контенту. Це значна зміна порівняно з простими текстовими відповідями, з якими ви працювали раніше.

![image_24_1](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623695%2F06_-_005_-_Handling_Message_Blocks_07.1748623695372.png)

Багатоблокове повідомлення зазвичай містить:

- **Text Block** - Людинозрозумілий текст, що пояснює, що робить Клод (наприклад, "Я можу допомогти вам дізнатися поточний час. Дозвольте мені знайти цю інформацію для вас")
- **ToolUse Block** - Інструкції для вашого коду про те, який інструмент викликати і які параметри використовувати

Блок ToolUse містить:

- ID для відстеження виклику інструмента
- Назву функції для виклику (наприклад, "get_current_datetime")
- Вхідні параметри, відформатовані як словник
- Позначення типу "tool_use"

### Керування історією розмов за допомогою багатоблокових повідомлень (Managing Conversation History with Multi-Block Messages)

Пам'ятайте, що Клод не зберігає історію розмов - вам потрібно керувати нею вручну. Працюючи з відповідями інструментів, ви повинні зберегти всю структуру контенту, включаючи всі блоки.

Ось як правильно додати багатоблокове повідомлення асистента до вашої історії розмов:

```python
messages.append({
    "role": "assistant",
    "content": response.content
})
```

Це зберігає як текстовий блок, так і блок використання інструмента, що є критично важливим для підтримки контексту розмови, коли ви робите наступні API-запити.

**💡 Tips (Збереження контексту багатоблокових повідомлень)**: Не намагайтеся витягти лише текст і передати його назад — API видасть помилку, якщо інструмент не матиме відповідного контексту.
**🚀 Use cases (Розбір та відображення кроків мислення моделі)**: Показ користувачу "Loading... Model is searching for X" під час опрацювання ToolUse блоку.

## Повний потік використання інструменту (The Complete Tool Usage Flow)

![image_26_1](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623696%2F06_-_005_-_Handling_Message_Blocks_15.1748623696291.png)

Процес використання інструмента відповідає такому шаблону:

1. Відправити повідомлення користувача зі схемою інструмента до Клода
2. Отримати повідомлення асистента з текстовим блоком та блоком використання інструмента
3. Витягти інформацію про інструмент і виконати фактичну функцію
4. Відправити результат інструмента назад Клоду разом з повною історією розмови
5. Отримати фінальну відповідь від Клода

Кожен крок вимагає обережної обробки структури повідомлень, щоб гарантувати, що Клод має повний контекст, необхідний для надання точних відповідей.

### Оновлення допоміжних функцій (Updating Helper Functions)

Якщо ви використовували допоміжні функції, такі як `add_user_message()` та `add_assistant_message()`, вам потрібно буде оновити їх для обробки багатоблокового контенту. Поточні версії, швидше за все, підтримують лише окремі текстові блоки, але тепер їм потрібно вміщувати складніші структури контенту, які включають блоки використання інструментів.

Ця обробка багатоблокових повідомлень є необхідною для створення надійних додатків, які можуть безшовно інтегрувати можливості інструментів Клода, зберігаючи при цьому правильний потік розмови.

**💡 Tips (Правильний життєвий цикл виклику інструмента)**: Обов'язково тестуйте весь ланцюжок від запиту до відповіді, щоб впевнитися, що ви ніде не губите історію.
**🚀 Use cases (Створення обгорток над Anthropic API)**: Створення власних клієнтів, які автоматично викликають Python-функції і повертають готовий текст.

## Відправка результатів інструмента (Sending tool results)

Після того, як Клод запитує виклик інструмента, вам потрібно виконати функцію і надіслати результати назад. Це завершує робочий процес використання інструмента, надаючи Клоду інформацію, яку він запитував.

### Запуск функції інструмента (Running the Tool Function)

Коли Клод відповідає блоком використання інструмента, ви витягуєте вхідні параметри та викликаєте вашу функцію. Ось як отримати доступ до параметрів інструмента:

```python
response.content[1].input
```

Це дає вам словник аргументів, які Клод хоче передати у вашу функцію. Оскільки ваша функція очікує іменовані аргументи (keyword arguments), а не словник, ви використовуєте синтаксис розпакування Python:

```python
get_current_datetime(**response.content[1].input)
```

### Блок результату інструмента (Tool Result Block)

Після запуску функції tool вам потрібно надіслати результати назад Клоду за допомогою блоку результатів tool. Цей блок розміщується всередині повідомлення користувача та повідомляє Клоду, що сталося під час виконання інструменту.

![image_30_1](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623701%2F06_-_006_-_Sending_Tool_Results_05.1748623701131.png)

Блок результату інструмента має кілька важливих властивостей:

- **tool_use_id** - Повинен збігатися з id блоку ToolUse, якому відповідає цей ToolResult
- **content** - Вивід від запуску вашого інструмента, серіалізований як рядок
- **is_error** - True, якщо сталася помилка

**💡 Tips (Зв'язування запиту і результату через ID)**: Кожен `tool_use_id` унікальний і генерується Клодом. Ви завжди повинні повертати саме його.
**🚀 Use cases (Повернення даних бази даних як рядка)**: Використання `json.dumps()` для перетворення складних об'єктів з БД у рядок для Клода.

### Створення подальшого запиту (Building the Follow-up Request)

Ваш наступний запит до Клода повинен містити повну історію розмов плюс новий результат інструмента. Ось структура:

messages.append({

### Робимо фінальний запит (Making the Final Request)

При надсиланні подальшого запиту ви все одно повинні включити схему інструмента, навіть якщо ви не очікуєте, що Клод зробить ще один виклик інструмента. Клоду потрібна схема, щоб зрозуміти посилання на інструменти у вашій історії розмов.

```python
def run_conversation(messages):
    while True:
        response = chat(messages)
        add_assistant_message(messages, response)

            break
            
        tool_result_blocks = run_tools(response)
        add_user_message(messages, tool_result_blocks)
        
    return messages
```

## Рефакторинг допоміжних функцій (Refactoring Helper Functions)

Перед реалізацією циклу розмови, вам потрібно оновити допоміжні функції для правильної обробки кількох блоків повідомлень.

### Оновлення обробників повідомлень (Updating Message Handlers)

Основна функція розмови слідує простому шаблону:

- `partial_json` - Фрагмент JSON, що представляє частину аргументів інструмента
- `snapshot` - Накопичений JSON, побудований з усіх отриманих фрагментів до цього моменту

Ось як ви обробляєте ці події у вашому стрімінговому конвеєрі:

```python
for chunk in stream:
    if chunk.type == "input_json":
        # Process the partial JSON chunk
        print(chunk.partial_json)
        # Or use the complete snapshot so far
        current_args = chunk.snapshot
```

### Як працює валідація JSON (How JSON Validation Works)

Тут стає цікаво. API Anthropic не надсилає вам кожен фрагмент одразу ж, коли Клод його генерує. Замість цього він буферизує фрагменти і спочатку перевіряє їх (валідує).

![image_60_1](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1752775509%2F06_-_011.1_-_Fine_Grained_Tool_Calling_08.1752775509598.png)

API чекає на повні пари ключ-значення на верхньому рівні перед відправкою будь-чого. Наприклад, якщо ваш інструмент очікує таку структуру:

```json
{
    "abstract": "This paper presents a novel...",
    "meta": {
        "word_count": 847,
        "review": "This paper introduces QuanNet..."
    }
}
```

API буде:

1. Чекати, поки все значення `abstract` буде завершено
2. Перевіряти цю пару ключ-значення відповідно до вашої схеми
3. Надсилати всі буферизовані фрагменти для `abstract` одночасно
4. Повторювати процес для об'єкта `meta`

![image_61_1](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1752775510%2F06_-_011.1_-_Fine_Grained_Tool_Calling_10.1752775510417.png)

Цей процес валідації пояснює, чому ви бачите затримки, за якими слідують сплески тексту, навіть з увімкненим стрімінгом. Фрагменти затримуються доти, поки не буде готова повна, валідна пара ключ-значення верхнього рівня.

![image_61_2](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1752775511%2F06_-_011.1_-_Fine_Grained_Tool_Calling_11.1752775511555.png)

### Дрібномодульний виклик інструментів (Fine-Grained Tool Calling)

Якщо вам потрібен швидший, більш деталізований стрімінг - можливо, щоб показувати користувачам негайні оновлення або швидше починати обробляти часткові результати - ви можете увімкнути "fine-grained tool calling".

![image_62_1](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1752775512%2F06_-_011.1_-_Fine_Grained_Tool_Calling_13.1752775512126.png)

Fine-grained tool calling робить одну головну річ: вимикає валідацію JSON на стороні API. Це означає:

- Ви отримуєте фрагменти, як тільки Клод їх генерує
- Немає затримок буферизації між ключами верхнього рівня
- Більш традиційна поведінка стрімінгу
- **Критично**: валідацію JSON вимкнено - ваш код повинен обробляти недійсний JSON

Увімкніть його, додавши `fine_grained=True` у ваш виклик API:

```python
run_conversation(
    messages,
    tools=[save_article_schema],
    fine_grained=True
)
```

З дрібномодульним викликом ви можете отримати значення `word_count` набагато раніше в потоці, не чекаючи завершення всього об'єкта `meta`.

### Обробка недійсного JSON (Handling Invalid JSON)

Коли ви використовуєте fine-grained tool calling, Клод може генерувати недійсний JSON, наприклад `"word_count": undefined` замість правильного числа. Вашому додатку потрібно витончено обробляти такі випадки:

```python
try:
    parsed_args = json.loads(chunk.snapshot)
except json.JSONDecodeError:
    # Handle invalid JSON appropriately
    print("Received invalid JSON, continuing...")
```

Без fine-grained tool calling валідація API відловила б цю помилку і потенційно загорнула б проблемні значення у рядки, які могли б не збігатися з вашою очікуваною схемою.

### Коли використовувати Fine-Grained Tool Calling

Розгляньте можливість увімкнення fine-grained tool calling, коли:

- Вам потрібно показувати користувачам прогрес генерації аргументів інструмента в реальному часі
- Ви хочете почати обробляти часткові результати інструментів якнайшвидше
- Затримки буферизації негативно впливають на ваш користувацький досвід
- Вам комфортно реалізовувати надійну обробку помилок JSON

Для більшості додатків стандартна поведінка з валідацією є цілком прийнятною. Але коли вам потрібна ця додаткова чуйність (responsiveness), fine-grained tool calling дає вам контроль для отримання фрагментів так швидко, як Клод їх генерує.

**💡 Tips (Баланс між швидкістю та стабільністю)**: Використовуйте стандартний стрімінг для критичних бекенд-завдань, де цілісність даних важливіша за затримку.
**🚀 Use cases (Інтерфейси з живими оновленнями UI)**: Створення прогрес-барів або відображення частково заповненої форми під час генерації відповіді.

- **WebSearchResultBlock** - Окремі результати пошуку з назвами та URL-адресами
