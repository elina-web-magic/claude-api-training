## Чому вам потрібен сервер

Ви ніколи не повинні робити запити до API Anthropic безпосередньо з клієнтського коду. Ось чому:

- Для запитів API потрібен секретний ключ API для автентифікації  
- Розкриття цього ключа в клієнтському коді створює серйозну вразливість безпеки  
- Будь-хто може витягти ключ і робити несанкціоновані запити

Натомість ваш веб- або мобільний додаток надсилає запити до вашого власного сервера, який потім спілкується з API Anthropic, використовуючи безпечно збережений ключ.

Кожен запит повинен містити ці обов'язкові поля:

## Всередині обробки Claude

Коли Anthropic отримує ваш запит, Claude обробляє його через чотири основні етапи: токенізація, вбудовування (embedding), контекстуалізація та генерація.

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623277%2F03_-_001_-_Accessing_the_API_08.1748623277503.png)

### Токенізація

Спочатку Claude розбиває ваш вхідний текст на менші частини, які називаються токенами. Вони можуть бути цілими словами, частинами слів, пробілами або символами. Для простоти думайте про кожне слово як про один токен.

### Вбудовування (Embedding)

Кожен токен перетворюється на вбудовування (embedding) - довгий список чисел, який представляє всі можливі значення цього слова. Уявіть собі вбудовування як числові визначення, що фіксують семантичні зв'язки.

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623278%2F03_-_001_-_Accessing_the_API_10.1748623278148.png)  
Слова часто мають кілька значень. Наприклад, "квант" може стосуватися:

- Дискретної одиниці фізичної величини (фізика)  
- Квантової механіки або концепцій квантової фізики  
- Чогось надзвичайно малого або субатомного  
- Застосувань квантових обчислень

### Контекстуалізація

Claude уточнює кожне вбудовування на основі сусідніх слів, щоб визначити найбільш ймовірне значення в контексті. Цей процес коригує числові представлення, щоб виділити відповідне визначення.

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623278%2F03_-_001_-_Accessing_the_API_11.1748623278717.png)

### Генерація

Контекстуалізовані вбудовування проходять через вихідний шар, який обчислює ймовірності для кожного можливого наступного слова. Claude не завжди обирає слово з найвищою ймовірністю - він використовує поєднання ймовірності та контрольованої випадковості для створення природних, різноманітних відповідей.

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623279%2F03_-_001_-_Accessing_the_API_13.1748623279317.png)  
Після вибору кожного слова Claude додає його до послідовності і повторює весь процес для наступного слова.

## Коли Claude припиняє генерацію

Після кожного токена Claude перевіряє кілька умов, щоб вирішити, чи продовжувати:

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623280%2F03_-_001_-_Accessing_the_API_15.1748623279963.png)

- Досягнуто ліміту токенів - чи досягнуто вказаного вами обмеження?  
- Природне завершення - чи згенерував він токен кінця послідовності?  
- Стоп-послідовність - чи зустрів він наперед визначену стоп-фразу?

## Відповідь API

Коли генерація завершується, API надсилає назад структуровану відповідь, що містить:

- Message (Повідомлення) - Згенерований текст  
- Usage (Використання) - Кількість вхідних і вихідних токенів  
- Stop Reason (Причина зупинки) - Чому генерація завершилася

## Функція Create

Основою виконання запитів API є функція **client.messages.create()**. Ця функція вимагає трьох ключових параметрів:

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623269%2F03_-_003_-_Making_a_Request_09.1748623269461.png)

- model (модель) - Назва моделі Claude, яку ви хочете використовувати  
- max_tokens - Обмеження безпеки на довжину відповіді (а не ціль)  
- messages (повідомлення) - Історія розмови, яку ви надсилаєте Claude

Параметр **max_tokens** діє як механізм безпеки. Якщо ви встановите його на 1000, Claude припинить генерацію після 1000 токенів, навіть якщо йому є що ще сказати. Claude не намагається досягти цього ліміту - він просто пише те, що вважає за потрібне, і зупиняється, якщо досягає максимуму.

### Розуміння повідомлень

Повідомлення представляють розмову між вами та Claude, подібно до чат-додатка. Існує два типи повідомлень:

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623270%2F03_-_003_-_Making_a_Request_13.1748623270369.png)

- User messages (повідомлення користувача) - Контент, який ви хочете надіслати Claude (написаний людьми)  
- Assistant messages (повідомлення асистента) - Відповіді, згенеровані Claude

Кожне повідомлення є словником (dictionary) з роллю (**role**, "user" або "assistant") та вмістом (**content**, фактичний текст).

## Виконання вашого першого запиту

Ось повний приклад виконання запиту до Claude:

```python
message = client.messages.create(  
    model=model,  
    max_tokens=1000,  
    messages=[  
        {  
            "role": "user",  
            "content": "Що таке квантові обчислення? Дай відповідь одним реченням"  
        }  
    ]
)
```

Коли ви запустите цей код, Claude обробить ваш запит і поверне об'єкт response, що містить згенерований текст разом з метаданими про запит.

### Вилучення відповіді

Об'єкт response містить багато інформації, але зазвичай вам потрібен лише згенерований текст. Отримайте доступ до нього за допомогою:

```python
message.content[0].text
```

Це дасть вам чистий, читабельний результат на кшталт: "Квантові обчислення - це тип обчислень, який використовує принципи квантової механіки, такі як суперпозиція та заплутаність, для обробки інформації за допомогою квантових бітів (кубітів), потенційно вирішуючи певні складні проблеми в експоненційній мірі швидше за класичні комп'ютери."

З цими основами ви можете почати експериментувати з різними підказками та створювати більш складні взаємодії з Claude.

## Багатокрокові розмови

Під час роботи з API Anthropic і Claude існує ключова концепція, яку ви повинні розуміти: Claude не зберігає жодної історії ваших розмов. Кожен ваш запит є повністю незалежним і не має пам'яті про попередні обміни.

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623270%2F03_-_004_-_Multi-Turn_Conversations_01.1748623269971.png)  
Це означає, що якщо ви хочете провести багатокрокову розмову, де Claude пам'ятає контекст попередніх повідомлень, вам потрібно самостійно управляти станом розмови.

### Проблема з розмовами без стану

Припустімо, ви питаєте Claude: "Що таке квантові обчислення?" і отримуєте хорошу відповідь. Потім ви продовжуєте з проханням: "Напиши ще одне речення" - Claude не має уявлення, про що ви говорите. Він напише речення про щось абсолютно випадкове, оскільки не пам'ятає дискусії про квантові обчислення.

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623270%2F03_-_004_-_Multi-Turn_Conversations_02.1748623270625.png)

### Як працюють багатокрокові розмови

Щоб зберегти контекст розмови, вам потрібно зробити дві речі:

- Вручну підтримувати список усіх повідомлень у вашому коді  
- Надсилати повну історію повідомлень з кожним запитом

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623271%2F03_-_004_-_Multi-Turn_Conversations_05.1748623271251.png)  
Ось робочий процес, який насправді функціонує:

1. Надішліть ваше перше повідомлення користувача Claude  
2. Візьміть відповідь Claude і додайте її до списку повідомлень як повідомлення асистента  
3. Додайте ваше наступне запитання як ще одне повідомлення користувача  
4. Надішліть всю історію розмови до Claude

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623271%2F03_-_004_-_Multi-Turn_Conversations_08.1748623271832.png)

### Створення допоміжних функцій

Щоб полегшити керування розмовою, ви можете створити три допоміжні функції:

```python
def add_user_message(messages, text):  
    user_message = {"role": "user", "content": text}  
    messages.append(user_message)

def add_assistant_message(messages, text):  
    assistant_message = {"role": "assistant", "content": text}  
    messages.append(assistant_message)

def chat(messages):  
    message = client.messages.create(  
        model=model,  
        max_tokens=1000,  
        messages=messages,  
    )

    return message.content[0].text
```

### Збираємо все разом

Ось як ви використовуєте ці функції для підтримки розмови:

```python
# Починаємо з порожнього списку повідомлень  
messages = []

# Додаємо початкове запитання користувача  
add_user_message(messages, "Визнач квантові обчислення одним реченням")

# Отримуємо відповідь Claude  
answer = chat(messages)

# Додаємо відповідь Claude до історії розмови  
add_assistant_message(messages, answer)

# Додаємо наступне запитання  
add_user_message(messages, "Напиши ще одне речення")

# Отримуємо наступну відповідь з повним контекстом
final_answer = chat(messages)
```

Тепер Claude зрозуміє, що "Напиши ще одне речення" відноситься до розширення визначення квантових обчислень, оскільки ви надали повний контекст розмови.

Ці допоміжні функції будуть корисні протягом усієї вашої роботи з Claude, значно полегшуючи створення додатків, які можуть підтримувати змістовні розмови протягом кількох обмінів.

## Системні підказки (System prompts)

Системні підказки - це потужний спосіб налаштувати те, як Claude реагує на введення користувача. Замість того, щоб отримувати загальні відповіді, ви можете формувати тон, стиль та підхід Claude, щоб вони відповідали вашому конкретному випадку використання.

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623273%2F03_-_006_-_System_Prompts_00.1748623272065.png)

### Чому системні підказки важливі

Уявіть створення чат-бота - репетитора з математики. Коли учень запитує "Як мені вирішити 5x + 2 = 3 для x?", ви хочете, щоб Claude поводився як справжній репетитор, а не просто видавав відповідь. Хороший репетитор з математики повинен:

- Спочатку давати підказки, а не повні рішення  
- Терпляче проводити учнів через проблеми крок за кроком  
- Показувати рішення схожих завдань як приклади

Ви точно не хочете, щоб Claude:

- Негайно давав прямі відповіді  
- Казав учням просто скористатися калькулятором

### Як працюють системні підказки

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623273%2F03_-_006_-_System_Prompts_05.1748623273817.png)  
Системні підказки надають Claude вказівки щодо того, як відповідати. Ви визначаєте їх як звичайні рядки і передаєте у виклик функції create. Основні переваги:

- Системні підказки дають Claude керівництво, як відповідати  
- Claude намагатиметься відповідати так само, як відповіла б людина у вказаній ролі  
- Допомагає тримати Claude сфокусованим на завданні

Ось базова структура:

```python
system_prompt = """  
Ти - терплячий репетитор з математики.  
Не відповідай прямо на запитання учня.  
Керуй ними до вирішення крок за кроком.  
"""

client.messages.create(  
    model=model,  
    messages=messages,  
    max_tokens=1000,  
    system=system_prompt
)
```

### Відчуйте різницю

Без системної підказки Claude негайно дає повне покрокове рішення. Це може бути корисним, але це не заохочує учня продумувати проблему самостійно.

З системною підказкою математичного репетитора відповідь Claude кардинально змінюється. Замість надання повного рішення Claude ставить навідні запитання на кшталт: "Як ти думаєш, який був би хороший перший крок, щоб виокремити x? Подумай, яку операцію нам може знадобитися виконати з обох боків, щоб почати переміщувати члени рівняння."

### Створення гнучкої функції чату

Замість жорсткого кодування системних підказок ви можете зробити свою функцію чату більш універсальною, приймаючи системні підказки як параметри:

```python
def chat(messages, system=None):  
    params = {  
        "model": model,  
        "max_tokens": 1000,  
        "messages": messages,  
    }  

    if system:  
        params["system"] = system  
      
    message = client.messages.create(**params)

    return message.content[0].text
```

Цей підхід враховує важливу деталь: API Claude не приймає **system=None**, тому вам потрібно умовно включати параметр system лише тоді, коли він надається.

Тепер ви можете викликати свою функцію чату з системною підказкою або без неї:

```python
# Без системної підказки  
answer = chat(messages)

# Із системною підказкою  
system = """  
Ти - терплячий репетитор з математики.  
Не відповідай прямо на запитання учня.  
Керуй ними до вирішення крок за кроком.  
"""

answer = chat(messages, system=system)
```

Системні підказки мають важливе значення для створення AI-додатків, які поводяться послідовно та належним чином для своєї цільової мети. Вони перетворюють загальні відповіді AI у спеціалізовані взаємодії, що відповідають ролі.

## Температура (Temperature)

Температура - це потужний параметр, який контролює, наскільки передбачуваними або творчими будуть відповіді Claude. Розуміння того, як ефективно її використовувати, може значно покращити ваші AI-додатки.

### Як Claude генерує текст

Перш ніж заглибитися в температуру, корисно зрозуміти процес генерації тексту Claude. Коли ви надсилаєте Claude підказку на кшталт "Що ти думаєш?", він проходить через три ключові кроки:

- Токенізація - розбиття вашого введення на менші частини  
- Прогнозування - обчислення ймовірностей для можливих наступних слів  
- Вибірка - вибір токена на основі цих ймовірностей

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623338%2F03_-_008_-_Temperature_00.1748623338635.png)  
У цьому прикладі Claude може призначити ймовірність 30% для "про", 20% для "б", 10% для "з", і так далі. Потім модель вибирає один токен і повторює весь цей процес, щоб побудувати повні речення.

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623339%2F03_-_008_-_Temperature_05.1748623339740.png)

### Що робить температура

Температура - це десяткове значення між 0 і 1, яке безпосередньо впливає на ці ймовірності вибору. Це ніби регулювання "регулятора креативності" у відповідях Claude.

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623340%2F03_-_008_-_Temperature_06.1748623340446.png)  
При низьких температурах (близько до 0) Claude стає дуже детермінованим - він майже завжди обирає токен з найвищою ймовірністю. При високих температурах (близько до 1) Claude розподіляє ймовірність більш рівномірно серед варіантів, що призводить до більш різноманітних та творчих результатів.

### Інтерактивна демонстрація температури

Ви можете побачити температуру в дії за допомогою інтерактивної демонстрації Claude. Спостерігайте, як розподіл ймовірностей змінюється під час регулювання повзунка температури:

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623341%2F03_-_008_-_Temperature_07.1748623341049.png)  
При температурі 0.0 "про" отримує 100% ймовірність - це повністю детерміновано. При температурі 1.0 ймовірності розподіляються більш рівномірно між усіма можливими токенами, привносячи випадковість та креативність.

### Вибір правильної температури

Різні завдання вимагають різних діапазонів температури:

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623341%2F03_-_008_-_Temperature_10.1748623341732.png)

### Низька температура (0.0 - 0.3)

- Фактичні відповіді  
- Допомога з програмуванням  
- Вилучення даних  
- Модерація контенту

### Середня температура (0.4 - 0.7)

- Підсумовування  
- Освітній контент  
- Вирішення проблем  
- Творче письмо з обмеженнями

### Висока температура (0.8 - 1.0)

- Мозковий штурм  
- Творче письмо  
- Маркетинговий контент  
- Генерація жартів

### Реалізація температури в коді

Додавання підтримки температури до вашої функції чату є простим. Ось як змінити вашу існуючу функцію:

```python
def chat(messages, system=None, temperature=1.0):  
    params = {  
        "model": model,  
        "max_tokens": 1000,  
        "messages": messages,  
        "temperature": temperature  
    }  

    if system:  
        params["system"] = system  
      
    message = client.messages.create(**params)

    return message.content[0].text
```

Ключовими змінами є додавання **temperature=1.0** як параметра та включення **"temperature": temperature** до словника params.

### Тестування впливу температури

Щоб побачити температуру в дії, спробуйте генерувати ідеї для фільмів з різними налаштуваннями:

```python
# Низька температура - більш передбачувано  
answer = chat(messages, temperature=0.0)

# Висока температура - більш креативно  
answer = chat(messages, temperature=1.0)
```

При температурі 0.0 ви можете послідовно отримувати відповіді на кшталт "Археолог, що мандрує в часі, повинен запобігти викраденню стародавніх артефактів". При температурі 1.0 ви побачите набагато більшу різноманітність у темах, персонажах та елементах сюжету.

### Основні висновки

Пам'ятайте, що температура не гарантує різних результатів - вона лише змінює ймовірність їх отримання. Навіть при високих температурах Claude може іноді давати схожі відповіді. Ключ полягає в тому, щоб підібрати вибір температури під ваш конкретний випадок використання:

- Потрібні послідовні, фактичні відповіді? Використовуйте низьку температуру  
- Хочете творчий мозковий штурм? Підвищуйте температуру  
- Щось посередині? Середні температури добре працюють для більшості загальних завдань

Температура - це один з найбільш практичних параметрів, які ви можете налаштувати для точного регулювання поведінки Claude під ваші конкретні потреби.

## Структуровані дані

Коли вам потрібно, щоб Claude згенерував структуровані дані, такі як JSON, код Python або марковані списки, ви часто стикатиметеся з типовою проблемою: Claude хоче бути корисним і додає пояснювальний текст навколо вашого контенту. Хоча зазвичай це чудово, іноді вам потрібні лише сирі дані і нічого більше.

Уявіть створення веб-додатка, який генерує правила AWS EventBridge. Користувачі вводять опис, натискають генерувати і очікують побачити чистий JSON, який вони можуть відразу скопіювати і використати. Якщо Claude повертає JSON, загорнутий у блоки коду markdown з пояснювальним текстом, користувачі не можуть просто скопіювати всю відповідь - їм доведеться вручну виділяти лише частину JSON.

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623326%2F03_-_011_-_Structured_Data_02.1748623325858.png)

## Проблема зі стандартними відповідями

За замовчуванням, коли ви просите Claude згенерувати JSON, ви можете отримати щось подібне:

```json
{  
  "source": ["aws.ec2"],  
  "detail-type": ["EC2 Instance State-change Notification"],  
  "detail": {  
    "state": ["running"]  
  }  
}  
```
Це правило фіксує зміни стану екземпляра EC2, коли екземпляри починають працювати.

JSON правильний, але він загорнутий у форматування markdown та містить пояснювальний текст. Для веб-додатка, де користувачам потрібно скопіювати сирий JSON, це створює перешкоди у взаємодії з користувачем.

## Рішення: Попереднє заповнення повідомлення асистента + Стоп-послідовності

Ви можете поєднати попереднє заповнення повідомлення асистента (prefilling) зі стоп-послідовностями (stop sequences), щоб отримати саме той контент, який ви хочете. Ось як це працює:

```python
messages = []

add_user_message(messages, "Згенеруй дуже коротке правило event bridge у форматі json")  
add_assistant_message(messages, "```json")

text = chat(messages, stop_sequences=["```"])
```

Ця техніка працює завдяки:

1. Повідомлення користувача каже Claude, що згенерувати  
2. Попередньо заповнене повідомлення асистента змушує Claude думати, що він уже почав блок коду markdown  
3. Claude продовжує, пишучи лише вміст JSON  
4. Коли Claude намагається закрити блок коду за допомогою **```**, стоп-послідовність негайно завершує генерацію

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748623327%2F03_-_011_-_Structured_Data_15.1748623326804.png)  
В результаті ми отримуємо чистий JSON без зайвого форматування:

```json
{  
  "source": ["aws.ec2"],  
  "detail-type": ["EC2 Instance State-change Notification"],  
  "detail": {  
    "state": ["running"]  
  }
}
```

### Обробка відповіді

Ви можете помітити кілька зайвих символів нового рядка у відповіді. Їх легко обробити:

```python
import json

# Очищення та парсинг JSON
clean_json = json.loads(text.strip())
```

### Більше ніж JSON

Ця техніка не обмежується лише генерацією JSON. Використовуйте її щоразу, коли вам потрібні структуровані дані без коментарів:

- Фрагменти коду Python  
- Марковані списки  
- Дані CSV  
- Будь-який відформатований вміст, де ви хочете отримати лише зміст, а не пояснення

Ключовим є визначення того, у що Claude природно хоче загорнути ваш контент, а потім використання цього як вашого попереднього заповнення (prefill) та стоп-послідовності (stop sequence). Для коду це зазвичай блоки коду markdown. Для списків це можуть бути інші маркери форматування.

Цей підхід дає вам точний контроль над форматом виводу Claude, значно полегшуючи інтеграцію згенерованого AI контенту в додатки, де чисті структуровані дані є важливими.
