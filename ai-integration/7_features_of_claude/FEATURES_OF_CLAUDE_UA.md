## 1. Розширене мислення (Extended Thinking)

### Завантаження

- [001_thinking.ipynb](./001_thinking.ipynb)

> [!IMPORTANT]

Повний список обмежень дивіться тут: [Feature Compatibility](https://docs.anthropic.com/en/docs/build-with-claude/extended-thinking#feature-compatibility)

### Що таке Extended Thinking?

Розширене мислення — це просунута функція міркування Claude, яка дає моделі час для опрацювання складних задач **перед** генерацією фінальної відповіді. Уявіть це як «чернетку» Claude — ви можете бачити процес міркування, який призводить до відповіді, що підвищує прозорість і часто покращує якість відповідей.

> [!TIP]
> **Аналогія:** Уявіть, що ви попросили когось вирішити складне рівняння. Без Extended Thinking — це як отримати тільки відповідь. З Extended Thinking — ви бачите весь ланцюг міркувань на «чернетці», перш ніж буде дано фінальну відповідь. Це особливо корисно для задач з математики, логіки, програмування та складного аналізу.

Коли розширене мислення увімкнено, відповідь Claude змінюється з простого текстового блоку на структуровану відповідь із двох частин:

З увімкненим мисленням ви отримуєте і процес міркування, і фінальну відповідь:

![Структура підпису: Assistant Message містить thinking block з підписом та text block з відповіддю](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542429%2F08_-_001_-_Extended_Thinking_05.1748542429732.jpg)

### Ключові переваги

- ✅ Кращі можливості міркування для складних задач
- ✅ Підвищена точність при розв'язанні складних проблем
- ✅ Прозорість процесу мислення Claude

### Компроміси

- ⚠️ Вищі витрати (ви платите за thinking-токени)
- ⚠️ Збільшена затримка (мислення потребує часу)
- ⚠️ Складніша обробка відповідей у вашому коді

> [!NOTE]
> **Коментар:** На практиці вартість thinking-токенів може бути суттєвою. Наприклад, якщо Claude використовує 5000 thinking-токенів на кожен запит, а ви робите 1000 запитів на день — це додаткові 5 мільйонів токенів на добу. Завжди тестуйте з бюджетом та без нього, щоб зрозуміти, чи варта ця якість додаткових витрат.

### Коли використовувати розширене мислення

Рішення просте: **використовуйте оцінку своїх промптів**. Спочатку запустіть промпти без мислення, і якщо точність не відповідає вашим вимогам після оптимізації промпту, тоді розгляньте можливість увімкнення розширеного мислення. Це інструмент для випадків, коли стандартний промпт не дає достатньо точних результатів.

> [!TIP]
> **Приклад реального сценарію:** Якщо ви просите Claude класифікувати тональність відгуків (позитивний/негативний/нейтральний) — стандартного промпту зазвичай достатньо. Але якщо ви просите проаналізувати складний юридичний документ з багатоступеневим логічним висновком — Extended Thinking може значно покращити результат.

### Структура відповіді та безпека

Відповіді з розширеним мисленням включають спеціальну систему підписів для безпеки:

![Структура підпису в Assistant Message з криптографічним токеном](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542430%2F08_-_001_-_Extended_Thinking_06.1748542430208.jpg)

Підпис — це **криптографічний токен**, який гарантує, що ви не змінили текст мислення. Це запобігає підробці розробниками процесу міркування Claude, що потенційно могло б направити модель у небезпечному напрямку.

> [!NOTE]
> **Чому це важливо?** Уявіть, що зловмисник перехопив відповідь Claude і змінив thinking block, щоб «переконати» Claude в наступному запиті, що він раніше міркував у певному (шкідливому) напрямку. Підпис запобігає таким атакам.

### Редаговане мислення (Redacted Thinking)

Іноді замість тексту міркування ви отримаєте **редагований** (приховуваний) блок мислення:

![Редагований блок мислення — приховуваний контент](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542430%2F08_-_001_-_Extended_Thinking_08.1748542430775.jpg)

Це трапляється, коли процес мислення Claude позначається внутрішніми системами безпеки. Редагований контент містить фактичне мислення в зашифрованому вигляді, що дозволяє передати повне повідомлення назад до Claude в майбутніх розмовах без втрати контексту.

> [!NOTE]
> **Коментар:** На практиці Redacted Thinking трапляється відносно рідко і зазвичай пов'язане з обговоренням чутливих тем. Ваш додаток повинен бути готовий обробляти такі блоки — просто передавайте їх назад в Claude як є, без спроб декодувати.

### Реалізація

Щоб увімкнути розширене мислення у вашому коді, потрібно додати два параметри до функції chat:

```python
def chat(
    messages,
    system=None,
    temperature=1.0,
    stop_sequences=[],
    tools=None,
    thinking=False,          # ← Новий параметр
    thinking_budget=1024     # ← Новий параметр
):
```

**Бюджет мислення** встановлює максимальну кількість токенів, які Claude може використовувати для міркування:

- **Мінімальне значення:** 1024 токени
- Параметр `max_tokens` **повинен бути більший** за thinking budget

Додайте конфігурацію мислення до параметрів API:

```python
if thinking:
    params["thinking"] = {
        "type": "enabled",
        "budget": thinking_budget
    }
```

Потім виклик із увімкненим мисленням:

```python
chat(messages, thinking=True)
```

> [!TIP]
> **Практична порада:** Починайте з мінімального бюджету (1024 токени) і збільшуйте його тільки якщо бачите, що Claude «обрізає» своє мислення. Для більшості задач 2048–4096 токенів більш ніж достатньо. Для дуже складних математичних чи кодових задач можете збільшити до 8192+.

### Тестування редагованих відповідей

Для тестування ви можете змусити Claude повернути редагований блок мислення, надіславши спеціальний тригерний рядок. Це допомагає переконатися, що ваш додаток коректно обробляє редаговані відповіді без збоїв.

> [!IMPORTANT]
> Розширене мислення — це потужна функція, коли вам потрібно, щоб Claude впорався зі складними задачами на міркування, але використовуйте її **обдумано** з огляду на вартість і затримку. Почніть зі стандартного промпту, оптимізуйте його, а потім додайте мислення, коли вам потрібна ця додаткова здатність до міркування.

## 2. Підтримка зображень (Image Support)

### Завантаження 1

- [images](./images)

Можливості зору Claude дозволяють включати зображення у ваші повідомлення та просити Claude аналізувати їх безліччю способів. Ви можете попросити Claude описати, що зображено на картинці, порівняти кілька зображень, підрахувати об'єкти або виконати складні задачі візуального аналізу.

### Основи роботи з зображеннями

![Обробка зображень: обмеження та код для включення зображення в повідомлення](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542455%2F08_-_002_-_Image_Support_01.1748542455758.jpg)

Є кілька важливих обмежень при роботі з зображеннями:

| Обмеження | Значення |
| ----------- | ---------- |
| Макс. зображень в одному запиті | До 100 (через усі повідомлення) |
| Макс. розмір одного зображення | 5 МБ |
| Макс. висота/ширина (одне зображення) | 8000 px |
| Макс. висота/ширина (кілька зображень) | 2000 px |
| Формати включення | Base64 або URL |
| Розрахунок токенів | `tokens = (width_px × height_px) / 750` |

> [!TIP]
> **Формула токенів на практиці:** Зображення 1920×1080 = ~2 765 токенів. Зображення 4000×3000 = 16 000 токенів! Завжди зменшуйте зображення до мінімально необхідного розміру, щоб заощадити на токенах і пришвидшити обробку.

Щоб надіслати зображення до Claude, включіть блок зображення у ваше повідомлення поруч з текстовими блоками. Ось структура:

```python
with open("image.png", "rb") as f:
    image_bytes = base64.standard_b64encode(f.read()).decode("utf-8")

add_user_message(messages, [
    # Блок зображення
    {
        "type": "image",
        "source": {
            "type": "base64",
            "media_type": "image/png",
            "data": image_bytes,
        }
    },
    # Текстовий блок
    {
        "type": "text",
        "text": "Що ви бачите на цьому зображенні?"
    }
])
```

> [!NOTE]
> **Коментар:** Зверніть увагу, що зображення можна також передавати через URL, а не тільки base64. Це зручніше для публічних зображень, оскільки не потрібно кодувати файл:
>
> ```python
> {
>     "type": "image",
>     "source": {
>         "type": "url",
>         "url": "https://example.com/image.png"
>     }
> }
> ```

### Техніки промптингу

![Порівняння простих та детальних промптів для аналізу зображень](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542457%2F08_-_002_-_Image_Support_04.1748542456885.jpg)

Ключ до отримання хороших результатів із зображеннями — застосування тих самих технік prompt engineering, які ви використовуєте з текстом. Прості промпти часто дають погані результати. Наприклад, запитання «Скільки кульок на цьому зображенні?» може повернути неправильний підрахунок.

Ви можете значно покращити точність Claude:

- 📌 Надаючи детальні інструкції та кроки аналізу
- 📌 Використовуючи one-shot або multi-shot приклади
- 📌 Розбиваючи складні задачі на менші кроки

### Покроковий аналіз

![Покроковий аналіз: детальна методологія для підрахунку об'єктів](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542457%2F08_-_002_-_Image_Support_05.1748542457338.jpg)

Замість простого запитання, надайте Claude методологію:

```text
Проаналізуйте це зображення з кульками та визначте точну кількість,
використовуючи цю методологію:

1. Почніть з ідентифікації кожної унікальної кульки по одній.
   Присвойте кожній номер при ідентифікації.

2. Перевірте результат, підрахувавши іншим методом.
   Починайте з нижнього лівого кута та рухайтесь рядок за рядком,
   зліва направо.

Яка точна, підтверджена кількість кульок на цьому зображенні?
```

> [!TIP]
> **Про Chain-of-Thought у візуальних задачах:** Ця техніка є прикладом «ланцюжка міркувань» (Chain-of-Thought) для візуальних задач. Вона змушує Claude «сповільнити» і систематично аналізувати зображення, замість того щоб давати швидку (і часто неправильну) інтуїтивну відповідь.

### Реальний приклад: оцінка пожежного ризику

![Приклад: аналіз супутникових знімків для оцінки пожежного ризику](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542458%2F08_-_002_-_Image_Support_08.1748542458276.jpg)

Ось практичне застосування: автоматизація оцінок пожежного ризику для страхування житла. Замість відправки інспекторів на кожну нерухомість, страхові компанії можуть використовувати супутникові знімки та аналіз Claude.

Система аналізує супутникові зображення для виявлення:

- 🌲 Густих, щільно розташованих дерев поблизу будинку
- 🚒 Складних маршрутів доступу для аварійних служб
- 🏠 Гілок, що нависають над будинком

Замість простого промпту «надайте оцінку пожежного ризику», добре структурований промпт розбиває аналіз на конкретні кроки:

```text
Проаналізуйте прикріплений супутниковий знімок нерухомості за такими кроками:

1. Ідентифікація будинку: знайдіть основний будинок на ділянці, шукаючи:
   - Найбільшу споруду з дахом
   - Типові ознаки житлового будинку (під'їзна дорога, правильна геометрія)
   - Відмінність від інших споруд (гаражі, сараї, басейни)

2. Аналіз нависання дерев: дослідіть усі дерева поблизу будинку:
   - Визначте дерева, крона яких простягається безпосередньо над дахом
   - Оцініть відсоток даху, покритого нависаючими гілками (0-25%, 25-50%, 50-75%, 75%+)
   - Зверніть увагу на особливо густі ділянки нависання

3. Оцінка пожежного ризику: для нависаючих дерев оцініть:
   - Потенційну вразливість до лісових пожеж
   - Близькість до димарів, вентиляційних отворів
   - Ділянки, де гілки створюють «міст» між рослинністю та будівлею

4. Ідентифікація захисного простору: оцініть загальну рослинну структуру ділянки:
   - Визначте, чи з'єднуються дерева, утворюючи суцільний полог
   - Зверніть увагу на «паливні драбини» (рослинність, яка може переносити вогонь)

5. Рейтинг пожежного ризику: на основі аналізу присвойте рейтинг від 1 до 4:
   - Рейтинг 1 (Низький ризик): Немає гілок над дахом, хороший захисний простір
   - Рейтинг 2 (Помірний ризик): Мінімальне нависання (<25% даху)
   - Рейтинг 3 (Високий ризик): Значне нависання (25-50% даху)
   - Рейтинг 4 (Критичний ризик): Масштабне нависання (>50% даху)
```

> [!TIP]
> **Порада:** Цей приклад чудово ілюструє, як Claude може замінити рутинну роботу експертів у визначених доменах. Подібний підхід можна застосувати для аналізу фото ушкоджень автомобілів (страхування), медичних знімків (попередній скринінг), архітектурних планів тощо.
>
> [!IMPORTANT]
> Пам'ятайте: ті самі техніки промптингу, що працюють для тексту, працюють і для зображень. Інвестуйте час у створення детальних, структурованих промптів, а не покладайтеся на прості запитання, якщо хочете отримати надійні результати.

## 3. Підтримка PDF

### Завантаження 2

- [earth.pdf](./earth.pdf)

Claude може читати та аналізувати PDF-файли безпосередньо, що робить його потужним інструментом для обробки документів. Ця можливість працює подібно до обробки зображень, але з кількома ключовими відмінностями у структурі коду.

### Налаштування обробки PDF

Для обробки PDF-файлу з Claude ви використовуєте практично ідентичний код до того, що використовується для зображень. Головні відмінності — у специфікаціях типу файлу та назвах змінних для ясності.

Ось як модифікувати існуючий код обробки зображень для PDF:

```python
with open("earth.pdf", "rb") as f:
    file_bytes = base64.standard_b64encode(f.read()).decode("utf-8")

messages = []

add_user_message(
    messages,
    [
        {
            "type": "document",           # ← "document" замість "image"
            "source": {
                "type": "base64",
                "media_type": "application/pdf",  # ← PDF media type
                "data": file_bytes,
            },
        },
        {"type": "text", "text": "Підсумуйте документ одним реченням"},
    ],
)

chat(messages)
```

### Ключові зміни порівняно з обробкою зображень

| Параметр | Зображення | PDF |
| ---------- | ----------- | ----- |
| Розширення файлу | `.png`, `.jpg` | `.pdf` |
| Назва змінної | `image_bytes` | `file_bytes` |
| Тип блоку | `"image"` | `"document"` |
| Media type | `"image/png"` | `"application/pdf"` |

### Що Claude може витягти з PDF

Можливості обробки PDF Claude виходять за межі простого вилучення тексту. Він може аналізувати та розуміти:

- 📄 Текстовий контент по всьому документу
- 📊 Зображення та графіки, вбудовані в PDF
- 📋 Таблиці та взаємозв'язки їхніх даних
- 📐 Структуру та форматування документа

Це робить Claude, по суті, універсальним рішенням для вилучення будь-якого типу інформації з PDF-документів — будь то резюме, аналіз даних чи конкретне вилучення контенту.

![Приклад обробки PDF: стаття Wikipedia про Землю, надіслана до Claude для аналізу](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542484%2F08_-_003_-_PDF_Support_02.1748542484779.jpg)

> [!NOTE]
> **Коментар:** Зверніть увагу, що Claude обробляє кожну сторінку PDF як окреме зображення. Тому великі PDF можуть споживати значну кількість токенів. 10-сторінковий PDF може легко використати 20 000+ токенів тільки на вхідні дані. Якщо вам потрібен тільки текст, розгляньте можливість попереднього вилучення тексту і надсилання його як простого тексту — це значно дешевше.
>
> [!TIP]
> **Практичний приклад:** PDF чудово підходять для аналізу контрактів, накладних, рахунків-фактур, наукових статей та технічної документації. Ви можете попросити Claude: «Знайди всі суми в цій накладній та поверни їх у форматі JSON» або «Порівняй умови в цих двох контрактах».

### Аналіз вартості та вибір моделей (Зображення/PDF vs Текст)

При роботі з мультимодальними даними важливо розуміти, як різні моделі тарифікують обробку.
Існує припущення, що обробляти зображення дешевше за текст. Це **частково правда**, але виключно для специфічних типів даних:

- **Звичайний текст (книги, контракти, статті):** Вилучення тексту (наприклад, через `PyMuPDF`) завжди значно дешевше (1 сторінка = ~800-1000 токенів тексту). Якщо передати цю ж сторінку як нативний PDF або зображення в Claude, вона буде масштабована, розбита на фрагменти (tiles) по 1601 токену і коштуватиме **від 3000 до 6000 токенів**.
- **Структуровані дані (Excel, графіки, матриці):** Форматування таблиці на 100 рядків у Markdown споживає величезну кількість токенів (кожен символ і пробіл рахується). У таких випадках відправити скріншот таблиці буде в кілька разів дешевшим, ніж її текстовий Markdown-аналог.

**Стратегії використання моделей Claude (станом на 2026 рік):**

1. **Claude 3.5 Sonnet:** Найкращий баланс. Це основна модель для візуальних задач. Завдяки високій точності і помірній ціні ідеально підходить для розпізнавання таблиць або скріншотів UI.
2. **Claude 3.5 Opus:** Найдорожча флагманська модель для складної логіки. **Уникайте передачі чисто текстових документів у форматі нативного PDF або зображень.** Завжди програмно витягуйте текст перед відправкою до Opus, інакше ви витратите великий бюджет на "роздивляння" літер.
3. **Claude Fable 5 (Agentic AI):** Модель для автономних агентів з глибоким кешуванням. Якщо ваш Web-агент робить десятки кроків, зчитування одного й того ж скріншоту з кешу (Cache Reads) стає надзвичайно дешевим, що робить передачу зображень архітектурно вигіднішою.

> [!IMPORTANT]
> **Контекст ринку:** Будьте уважні при міграції між вендорами. Наприклад, Google Gemini (1.5 Pro) має фіксовану вартість за зображення (258 токенів), що робить зображення майже завжди дешевшими за текст. OpenAI (GPT-4o) має економний режим `Low Detail` (85 токенів). Claude застосовує детальніший і дорожчий підхід (до 6000 токенів за великий файл), але це компенсується найвищою на ринку точністю розпізнавання дрібних деталей та таблиць.

## 4. Цитування (Citations)

### Завантаження 3

- [002_citations_complete.ipynb](./002_citations_complete.ipynb)
- [earth.pdf](./earth.pdf)

Коли Claude відповідає на запитання на основі наданих документів, користувачі можуть припустити, що він просто використовує свої тренувальні дані. Але що, якби Claude міг показати **точно**, де він знайшов конкретну інформацію? Саме для цього існують **цитати** — потужна функція, яка дозволяє Claude посилатися на конкретні частини ваших вихідних документів і показувати користувачам, звідки береться кожна частина інформації.

### Чому цитати важливі

Уявіть, що ви запитуєте Claude про формування атмосфери Землі та отримуєте детальну відповідь. Без цитат у користувачів немає способу перевірити інформацію або зрозуміти, що Claude фактично посилається на конкретний наданий документ. Цитати вирішують цю проблему прозорості, створюючи чіткий слід від відповіді Claude до вихідного матеріалу.

![Приклад цитування: Claude посилається на конкретні частини документа earth.pdf](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542499%2F08_-_004_-_Citations_00.1748542499688.jpg)

> [!NOTE]
> **Коментар:** Цитати — це критично важлива функція для enterprise-застосунків, де точність і верифікованість інформації є ключовими. Це особливо актуально для юридичних, медичних та фінансових додатків, де помилкова інформація може мати серйозні наслідки.

### Увімкнення цитат

Щоб увімкнути цитати, потрібно модифікувати структуру повідомлення з документом. Додайте два нових поля до блоку документа:

```python
{
    "type": "document",
    "source": {
        "type": "base64",
        "media_type": "application/pdf",
        "data": file_bytes,
    },
    "title": "earth.pdf",                # ← Заголовок документа
    "citations": { "enabled": True }     # ← Увімкнення цитат
}
```

Поле `title` надає документу читабельну назву, а `citations: {"enabled": True}` вказує Claude відстежувати, де він знаходить інформацію.

### Розуміння структури цитат

Коли цитати увімкнені, відповідь Claude стає складнішою. Замість простого тексту ви отримуєте структуровані дані з інформацією про цитування для кожного твердження.

![Структура цитат: cited_text, document_index, page numbers](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542500%2F08_-_004_-_Citations_08.1748542500257.jpg)

Кожна цитата містить кілька ключових елементів:

| Поле | Опис |
| ------ | ------ |
| `cited_text` | Точний текст з документа, який підтверджує твердження Claude |
| `document_index` | Який документ цитує Claude (корисно при кількох документах) |
| `document_title` | Заголовок, присвоєний документу |
| `start_page_number` | Де починається цитований текст |
| `end_page_number` | Де закінчується цитований текст |

![Приклад даних цитування в JSON-форматі](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542500%2F08_-_004_-_Citations_09.1748542500755.jpg)

### Створення інтерфейсів з цитатами

Справжня потужність цитат проявляється при створенні користувацьких інтерфейсів, які роблять цю інформацію доступною. Ви можете створити інтерактивні елементи, де користувачі можуть навести курсор на маркери цитат, щоб побачити, звідки саме надійшла інформація.

![Приклад UI з інтерактивними цитатами: при наведенні показується джерело](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542501%2F08_-_004_-_Citations_11.1748542501163.jpg)

- ✅ Бачити, що відповіді Claude ґрунтуються на реальному вихідному матеріалі
- ✅ Верифікувати інформацію, перевіряючи оригінальний документ

### Цитати з простим текстом

Цитати не обмежені PDF-документами. Ви можете також використовувати їх з текстовими джерелами. При роботі з текстом модифікуйте структуру документа так:

```python
{
    "type": "document",
    "source": {
        "type": "text",
        "media_type": "text/plain",
        "data": article_text,
    },
    "title": "earth_article",
    "citations": { "enabled": True }
}
```

> [!NOTE]
> **Різниця:** Для текстових джерел замість номерів сторінок ви отримаєте **позиції символів**, які точно вказують, де в тексті Claude знайшов кожну частину інформації. Це дозволяє підсвічувати конкретні фрагменти тексту в UI.

### Коли використовувати цитати

Цитати особливо цінні, коли:

- 📋 Користувачам потрібно верифікувати інформацію для точності
- 📚 Ви працюєте з авторитетними документами, на які користувачі повинні мати можливість посилатися
- 🔍 Прозорість джерел інформації є критичною для вашого додатку
- 🔎 Користувачі можуть захотіти дослідити ширший контекст навколо конкретних фактів

Впроваджуючи цитати, ви перетворюєте Claude з «чорної скриньки», яка надає відповіді, на **прозорого дослідницького асистента**, який показує свою роботу. Це будує довіру користувачів і дозволяє їм глибше вивчати ваші вихідні матеріали за потреби.

## 5. Кешування промптів (Prompt Caching)

Кешування промптів — це функція, яка **прискорює відповіді** Claude та **знижує вартість** генерації тексту шляхом повторного використання обчислювальної роботи з попередніх запитів. Замість того, щоб викидати всю роботу з обробки після кожного запиту, Claude може зберегти та повторно використати її, коли ви надсилаєте подібний контент знову.

### Як Claude зазвичай обробляє запити

Щоб зрозуміти кешування промптів, спочатку розглянемо, що відбувається під час типового запиту без увімкненого кешування.

![Схема звичайної обробки запиту Claude: передобробка та генерація](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542537%2F08_-_005_-_Prompt_Caching_01.1748542536808.jpg)

Коли ви надсилаєте повідомлення до Claude, він не починає одразу генерувати відповідь. Натомість Claude виконує величезну кількість роботи з передобробки вхідних даних:

- 🔤 **Токенізація** промпту на менші частини
- 🧮 **Створення ембедингів** для кожного токена
- 📝 **Додавання контексту** на основі оточуючого тексту
- ✍️ І тільки **потім** генерація вихідного тексту

![Деталі обчислювальної роботи при обробці запиту](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542537%2F08_-_005_-_Prompt_Caching_04.1748542537345.jpg)

Після надсилання відповіді Claude **викидає** всю цю обчислювальну роботу — токенізація, ембединги та аналіз контексту — все це видаляється.

![Claude повторно обробляє ідентичний контент](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542539%2F08_-_005_-_Prompt_Caching_11.1748542538911.jpg)

> **Аналогія:** Уявіть, що ви перекладач, і вас просять перекласти документ на 50 сторінок. Ви перекладаєте його, віддаєте переклад і... знищуєте всі свої нотатки та словниковий аналіз. Коли вас потім просять перекласти той самий документ, але з іншим стилем — ви починаєте все спочатку. Кешування — це як зберегти свої нотатки.

### Ключові переваги та обмеження

![Переваги кешування: швидші відповіді та менші витрати](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542540%2F08_-_005_-_Prompt_Caching_19.1748542540458.jpg)

**Переваги:**

- ⚡ **Швидші відповіді:** Запити з кешованим контентом виконуються швидше
- 💰 **Менші витрати:** Ви платите менше за кешовані частини ваших запитів
- 🔄 **Автоматична оптимізація:** Початковий запит записує в кеш, наступні — читають з нього

**Обмеження:**

- ⏰ **Тривалість кешу:** Кешований контент живе тільки **одну годину**
- 🔁 **Обмежені випадки використання:** Корисно тільки при повторному надсиланні того самого контенту
- 📊 **Вимога високої частоти:** Найефективніше, коли той самий контент з'являється надзвичайно часто у ваших запитах

> [!TIP]
> **Де кешування найбільш ефективне:**
>
> - Чат-боти з великим system prompt (наприклад, помічник з кодування з промптом на 6000 токенів)
> - Аналіз документів, де ви ставите кілька запитань до одного документа
> - Ітеративне редагування, де базовий контент лишається незмінним
> - Будь-який сценарій з повторним використанням tool schemas

## 6. Правила кешування промптів

### Точки зупинки кешу (Cache Breakpoints)

![Точки зупинки кешу: як вказати Claude, що потрібно кешувати](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542546%2F08_-_006_-_Rules_of_Prompt_Caching_00.1748542546287.jpg)

Кешування **не вмикається автоматично** — вам потрібно вручну додавати точки зупинки кешу (cache breakpoints) до конкретних блоків у ваших повідомленнях. Ось як це працює:

- ❌ Робота над повідомленнями **не кешується автоматично**
- ✅ Ви повинні **вручну** додати «cache breakpoint» до блоку
- ✅ Робота, виконана для **всього перед** точкою зупинки, буде кешована
- ⚠️ Кеш буде використаний у наступних запитах **тільки якщо контент** до включно з точкою зупинки **ідентичний**

![Порівняння скороченої та розширеної форми запису з cache_control](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542547%2F08_-_006_-_Rules_of_Prompt_Caching_04.1748542546894.jpg)

Щоб додати точку зупинки кешу, потрібно використовувати **розширену форму** для написання текстових блоків замість скороченої:

![image](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542547%2F08_-_006_-_Rules_of_Prompt_Caching_06.1748542547409.jpg)

Скорочена форма не передбачає місця для додавання поля керування кешем, тому потрібно використовувати розгорнутий формат із полем `cache_control`, встановленим на `{"type": "ephemeral"}`.

```python
# Скорочена форма (НЕ підтримує кешування):
{"role": "user", "content": "Привіт!"}

# Розширена форма (підтримує кешування):
{
    "role": "user",
    "content": [
        {
            "type": "text",
            "text": "Привіт!",
            "cache_control": {"type": "ephemeral"}   # ← Точка зупинки
        }
    ]
}
```

> [!NOTE]
> **Коментар:** Назва `"ephemeral"` (тимчасовий) вказує на те, що кеш — це тимчасове сховище, а не довготривале. Це підкреслює, що кеш живе лише одну годину.

### Як працюють точки зупинки кешу

Коли ви розміщуєте точку зупинки кешу в повідомленні, Claude кешує всю обробку **до і включно** з цією точкою. Контент після точки зупинки обробляється нормально без кешування.

![Кеш інвалідується при найменшій зміні контенту](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542547%2F08_-_006_-_Rules_of_Prompt_Caching_08.1748542547846.jpg)

Щоб кеш був корисним у наступних запитах, контент повинен бути **ідентичним** до точки зупинки. Навіть невеликі зміни, як додавання слова «будь ласка», **інвалідують кеш** і змушують Claude повторно обробити все.

![Приклад інвалідації кешу при зміні контенту](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542548%2F08_-_006_-_Rules_of_Prompt_Caching_10.1748542548220.jpg)

> [!WARNING]
> **Увага:** Кеш надзвичайно чутливий! Зміна навіть одного символу в кешованій частині запиту повністю інвалідує кеш для цього компонента. Це стосується пробілів, переносів рядків та навіть зміни регістру символів.

### Кешування між повідомленнями (Cross-Message Caching)

![Точки зупинки можуть охоплювати кілька повідомлень](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542548%2F08_-_006_-_Rules_of_Prompt_Caching_11.1748542548748.jpg)

Точки зупинки кешу можуть охоплювати кілька повідомлень та типів повідомлень. Якщо ви розміщуєте точку зупинки в пізнішому повідомленні, всі попередні повідомлення (user, assistant тощо) будуть включені в кешований контент.

Це особливо корисно для розмов, де ви хочете кешувати весь контекст до певної точки.

### Системні промпти та інструменти

Ви не обмежені текстовими блоками — точки зупинки кешу можна додати до:

- 📝 Системних промптів
- 🔧 Визначень інструментів
- 🖼️ Блоків зображень
- 🛠️ Блоків використання та результатів інструментів

![Кешування системних промптів та інструментів](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542549%2F08_-_006_-_Rules_of_Prompt_Caching_13.1748542549124.jpg)

Системні промпти та визначення інструментів є **відмінними кандидатами** для кешування, оскільки вони рідко змінюються між запитами. Саме тут ви зазвичай отримаєте найбільшу вигоду від кешування.

> [!TIP]
> **Практична порада:** Якщо у вас є застосунок з 10+ інструментами і великим системним промптом — кешування може заощадити до 90% витрат на передобробку цих компонентів. Це може означати суттєве зменшення загальних витрат на API.

### Порядок кешування

За лаштунками Claude обробляє компоненти вашого запиту в конкретному порядку: **інструменти** → **системний промпт** → **повідомлення**. Розуміння цього порядку допомагає ефективно розміщувати точки зупинки.

![Порядок обробки: tools → system → messages](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542550%2F08_-_006_-_Rules_of_Prompt_Caching_15.1748542549957.jpg)

Ви можете додати **до чотирьох** точок зупинки кешу загалом. Наприклад, ви можете кешувати інструменти, а потім додати ще одну точку зупинки посередині історії розмови.

![Приклад розміщення кількох точок зупинки](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542550%2F08_-_006_-_Rules_of_Prompt_Caching_17.1748542550452.jpg)

### Мінімальна довжина контенту

![Мінімальний поріг: 1024 токени для кешування](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542550%2F08_-_006_-_Rules_of_Prompt_Caching_19.1748542550839.jpg)

Є **мінімальний поріг** для кешування: контент повинен бути щонайменше **1024 токени**, щоб його можна було кешувати. Це сума всіх повідомлень і блоків, які ви намагаєтесь кешувати, а не окремих блоків.

Просте повідомлення «Привіт!» не досягне цього порогу, але якщо ви продублюєте цей контент 500 разів (або маєте дійсно довгий промпт), він перевищить 1024 токени і буде придатний для кешування.

> [!IMPORTANT]
> **Ключ до ефективного кешування промптів:** Визначте, які частини ваших запитів **лишаються незмінними** від виклику до виклику, і стратегічно розмістіть точки зупинки, щоб максимізувати повторне використання та мінімізувати інвалідацію кешу.

## 7. Кешування промптів на практиці

### Завантаження 4

- [003_caching.ipynb](./003_caching.ipynb)

Кешування промптів — це потужна функція оптимізації, яка робить ваші API-запити **швидшими** та **дешевшими**, коли ви повторно надсилаєте той самий контент до Claude. Розглянемо, як ефективно реалізувати її у ваших додатках.

### Як працює кешування промптів

![Огляд: перший запит записує в кеш, наступні читають з нього](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542595%2F08_-_007_-_Prompt_Caching_in_Action_19.1748542594923.jpg)

Коли ви вмикаєте кешування промптів, перший запит записує контент у кеш, який живе **одну годину**. Наступні запити можуть читати з цього кешу замість повторної обробки того самого контенту. Це особливо цінне, коли ви надсилаєте:

- 📝 **Великі системні промпти** (наприклад, промпт помічника з кодування на 6K токенів)
- 🔧 **Складні схеми інструментів** (близько 1.7K токенів для кількох інструментів)
- 📨 **Повторний контент повідомлень**

> [!NOTE]
> **Ключове розуміння:** Кешування допомагає тільки якщо ви повторно надсилаєте ідентичний контент — але в багатьох додатках це трапляється надзвичайно часто!

### Налаштування кешування схем інструментів

Щоб кешувати схеми інструментів, потрібно додати поле cache control до **останнього** інструмента у вашому списку. Ось правильний спосіб зробити це без модифікації оригінальних визначень інструментів:

```python
if tools:
    tools_clone = tools.copy()
    last_tool = tools_clone[-1].copy()
    last_tool["cache_control"] = {"type": "ephemeral"}
    tools_clone[-1] = last_tool
    params["tools"] = tools_clone
```

> [!TIP]
> **Чому копіювання?** Цей підхід створює копії як списку інструментів, так і останньої схеми інструмента перед додаванням поля cache control. Хоча ви могли б безпосередньо модифікувати `tools[-1]["cache_control"]`, підхід з копіюванням **запобігає проблемам**, якщо ви пізніше змінюєте порядок інструментів. Це захисне програмування!

### Кешування системних промптів

Для системних промптів потрібно структурувати їх як текстовий блок з керуванням кешем:

```python
if system:
    params["system"] = [
        {
            "type": "text",
            "text": system,
            "cache_control": {"type": "ephemeral"}
        }
    ]
```

Це перетворює системний промпт з простого рядка на структурований формат, який підтримує кешування.

### Розуміння поведінки кешу

Коли ви запускаєте запити з увімкненим кешуванням, ви побачите різні патерни використання у відповіді:

| Запит | Поле у відповіді | Значення |
| ------- | ----------------- | ---------- |
| **Перший запит** | `cache_creation_input_tokens=1772` | Claude **записує** в кеш |
| **Наступні запити** | `cache_read_input_tokens=1772` | Claude **читає** з кешу |
| **Змінений контент** | Нові `cache_creation` токени | Кеш **перезаписується** |

> [!WARNING]
> Кеш **надзвичайно чутливий** — зміна навіть одного символу в інструментах або системному промпті інвалідує **весь кеш** для цього компонента.

### Порядок кешування та точки зупинки

Ви можете встановити кілька точок зупинки кешу в одному запиті. Порядок має значення:

1. **Інструменти** (якщо надані)
2. **Системний промпт** (якщо наданий)
3. **Повідомлення**

Якщо ви змінюєте системний промпт, але залишаєте ті самі інструменти, ви побачите **часткове зчитування з кешу** (для інструментів) і **запис у кеш** (для нового системного промпту). Це гранулярне кешування означає, що ви платите тільки за обробку тих частин, які фактично змінилися.

> [!TIP]
> **Приклад економії:** Уявіть додаток з system prompt на 5000 токенів і 10 інструментами (2000 токенів). При 100 запитах на годину:
>
> - **Без кешування:** 100 × 7000 = 700 000 вхідних токенів
> - **З кешуванням:** 7000 (перший запит) + 99 × 0 (кешовані) = ~7 000 вхідних токенів
> - **Економія: ~99%** на вхідних токенах для кешованих компонентів!

### Практичні рекомендації

Кешування промптів найефективніше, коли у вас є:

- ✅ Стабільні схеми інструментів між запитами
- ✅ Незмінні системні промпти
- ✅ Додатки, які роблять багато запитів з подібним контекстом

> [!IMPORTANT]
> Пам'ятайте, що кеш живе тільки **одну годину**, тому він розрахований на додатки з відносно частим використанням API, а не на довготривале зберігання.

## 8. Виконання коду та Files API

### Завантаження 5

Anthropic API пропонує дві потужні функції, які чудово працюють разом: **Files API** та **Виконання коду (Code Execution)**. Хоча спочатку вони можуть здатися окремими, їх поєднання відкриває дійсно цікаві можливості для делегування складних задач Claude.

### Files API

Files API забезпечує альтернативний спосіб роботи з завантаженням файлів. Замість кодування зображень або PDF безпосередньо у ваших повідомленнях як base64-дані, ви можете **завантажити файли заздалегідь** і посилатися на них пізніше.

![Схема роботи Files API: завантаження файлу, отримання ID, посилання в повідомленнях](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542605%2F08_-_008_-_Code_Execution_and_the_Files_API_01.1748542605372.jpg)

Ось як це працює:

- 📤 **Завантажте** файл (зображення, PDF, текст тощо) до Claude через окремий API-виклик
- 🔑 **Отримайте** об'єкт метаданих файлу з унікальним ID
- 🔗 **Посилайтесь** на цей ID у майбутніх повідомленнях замість включення сирих даних файлу

![Приклад коду для використання Files API](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542606%2F08_-_008_-_Code_Execution_and_the_Files_API_02.1748542606050.jpg)

Цей підхід особливо корисний, коли ви хочете посилатися на **той самий файл кілька разів** або при роботі з великими файлами, які було б незручно включати в кожен запит.

> [!TIP]
> **Коментар:** Files API — це ідеальний підхід для додатків, де один і той самий документ аналізується з різних точок зору. Наприклад, ви завантажуєте PDF контракту один раз, а потім ставите 10 різних запитань про нього — без необхідності кожен раз передавати сам файл.

### Інструмент виконання коду (Code Execution Tool)

Виконання коду — це **серверний інструмент**, який не вимагає від вас надання реалізації. Ви просто включаєте попередньо визначену схему інструмента у ваш запит, і Claude може за потребою виконувати Python-код в ізольованому Docker-контейнері.

![Схема виконання коду: Claude запускає Python-код в ізольованому контейнері](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542607%2F08_-_008_-_Code_Execution_and_the_Files_API_04.1748542607054.jpg)

Ключові характеристики середовища виконання коду:

| Характеристика | Деталі |
| --------------- | -------- |
| Середовище | Ізольований Docker-контейнер |
| Мережевий доступ | ❌ Немає (не може робити зовнішні API-виклики) |
| Кількість виконань | Claude може виконувати код кілька разів під час однієї розмови |
| Результати | Перехоплюються та інтерпретуються Claude для фінальної відповіді |

> [!NOTE]
> **Коментар:** Відсутність мережевого доступу — це навмисне обмеження безпеки. Це означає, що Claude не може «втекти» з контейнера або надіслати ваші дані кудись. Але це також означає, що він не може встановити pip-пакети з інтернету — тільки попередньо встановлені бібліотеки доступні.

### Поєднання Files API та Code Execution

Справжня потужність проявляється при **спільному використанні** цих функцій. Оскільки Docker-контейнери не мають мережевого доступу, Files API стає **основним способом** передачі даних в середовище виконання та з нього.

![Workflow: Files API + Code Execution для повного циклу аналізу даних](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542607%2F08_-_008_-_Code_Execution_and_the_Files_API_06.1748542607578.jpg)

Ось типовий робочий процес:

1. 📤 **Завантажте** ваш файл даних (наприклад, CSV) через Files API
2. 📎 **Включіть** блок container upload у ваше повідомлення з file ID
3. ❓ **Попросіть** Claude проаналізувати дані
4. 🐍 Claude **пише та виконує** код для обробки вашого файлу
5. 📊 Claude може **генерувати результати** (наприклад, графіки), які ви можете завантажити

### Практичний приклад

Розглянемо реальний приклад з використанням даних стрімінгового сервісу. CSV-файл містить інформацію про користувачів, включаючи рівні підписки, звички перегляду та чи скасували вони підписку (churn).

![Приклад аналізу: завантаження CSV та запит на аналіз відтоку клієнтів](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542608%2F08_-_008_-_Code_Execution_and_the_Files_API_08.1748542608112.jpg)

Спочатку завантажте файл за допомогою допоміжної функції:

```python
file_metadata = upload('streaming.csv')
```

Потім створіть повідомлення, яке включає завантажений файл і запит на аналіз:

```python
messages = []
add_user_message(
    messages,
    [
        {
            "type": "text",
            "text": """Проведіть детальний аналіз для визначення
основних драйверів відтоку клієнтів.
            Ваш фінальний результат повинен включати щонайменше
один детальний графік із підсумком ваших висновків."""
        },
        {"type": "container_upload", "file_id": file_metadata.id},
    ],
)

chat(
    messages,
    tools=[{"type": "code_execution_20250522", "name": "code_execution"}]
)
```

> [!TIP]
> **Зверніть увагу** на тип інструмента `"code_execution_20250522"` — це версіонований ідентифікатор. Anthropic може випускати нові версії цього інструмента, тому завжди перевіряйте документацію на предмет останньої версії.

### Розуміння відповіді

Коли Claude використовує виконання коду, відповідь містить кілька типів блоків:

- 📝 **Text blocks** — аналіз та пояснення Claude
- 🖥️ **Server tool use blocks** — фактичний код, який Claude вирішив запустити
- 📊 **Code execution tool result blocks** — результат виконання коду

![Приклад відповіді з кількома блоками: текст, код, результати](https://everpath-course-content.s3-accelerate.amazonaws.com/instructor%2Fa46l9irobhg0f5webscixp0bs%2Fpublic%2F1748542608%2F08_-_008_-_Code_Execution_and_the_Files_API_13.1748542608585.jpg)

Claude може виконувати код **кілька разів** під час однієї відповіді, ітеративно побудовуючи свій аналіз. Кожен цикл виконання включає код та його результати.

> [!NOTE]
> **Коментар:** Це надзвичайно потужно, бо Claude може побачити помилку у своєму коді, виправити її та запустити знову — все автоматично. Він також може побачити проміжні результати та адаптувати свій аналіз відповідно. Це справжнє ітеративне програмування!

### Завантаження згенерованих файлів

Одна з найпотужніших функцій — здатність Claude **генерувати файли** (наприклад, графіки або звіти) та робити їх доступними для завантаження. Коли Claude створює візуалізацію, вона зберігається в контейнері, і ви можете завантажити її за допомогою Files API.

Шукайте блоки з `type: "code_execution_output"` у відповіді — вони містять file ID для згенерованого контенту:

```python
download_file("file_id_from_response")
```

Результатом є комплексний аналіз з професійними візуалізаціями, створення яких вручну потребувало б значних зусиль у написанні коду.
